# RoboTwin 2.0 论文解读与比赛改进计划

论文：[RoboTwin 2.0: A Scalable Data Generator and Benchmark with Strong Domain Randomization for Robust Bimanual Robotic Manipulation](https://arxiv.org/abs/2506.18088)。本说明面向 LingBot-VLA 2.0 初赛的 Aloha-AgileX 仿真任务。

## 先给结论

RoboTwin 2.0 说明：模型在干净演示上拟合成功，并不等于能在 randomized setting 成功。论文最有效的手段是用大规模随机化轨迹进行预训练；**该路线不适用于本比赛训练**，因为比赛只允许 50 个任务各 50 条 `clean` 数据，明确禁止使用 `randomized` 数据参与训练。

因此，本项目应把精力放在四件事：

1. 保证 LingBot-VLA 2.0、动作表示、相机和机器人状态与 RoboTwin 完全对齐。
2. 让有限的 clean 数据被均衡、稳定地使用，而不是盲目增加训练步数。
3. 在不引入 randomized 轨迹的前提下，改进动作监督和推理稳定性。
4. 用每任务的失败类型驱动下一轮调优，并保持训练、开发评测和正式评测可复现。

## 论文在做什么

### 1. 数据生成

论文构建了 RoboTwin-OD：731 个物体、147 个类别，并提供可抓取点、功能点和多样语言描述。基于该资产库，代码生成 agent 根据任务描述编写机器人程序；程序每轮在仿真中运行 10 次，系统记录失败原因，VLM observer 再定位具体失败步骤。程序达到目标成功率或连续修复 5 次后停止。

这部分的价值在于“先验证专家轨迹质量，再拿轨迹训练”。它不意味着比赛中可以再生成或混入额外轨迹；比赛数据范围以官方规则为准。

### 2. 五类随机化

论文的 randomized setting 同时变化：

| 维度 | 论文中的作用 | 对本比赛的含义 |
| --- | --- | --- |
| 干扰物 | 增加桌面杂物，但排除与目标物过于相似的物体 | randomized 评测会检验视觉选择和目标辨识。 |
| 背景与桌面纹理 | 降低对干净仿真背景的过拟合 | 训练输入预处理必须稳定，不能把背景当作任务线索。 |
| 光照 | 变化颜色、类型、强度和位置 | 要检查图像归一化、相机顺序和 RGB/BGR。 |
| 桌面高度 | 论文设置最高约 3 cm 的变化 | 需要依赖机器人状态和相对几何，不能只记忆像素位置。 |
| 语言指令 | 同一目标的多种表述 | 模型要稳定地把任务指令绑定到正确对象与动作。 |

### 3. 基准设定与结果

论文的基准与初赛核心设定一致：Aloha-AgileX、50 个任务、每任务 50 条 clean 演示训练；每个任务在 clean 和 domain-randomized 两种条件各测试 100 次。

论文中，预训练 VLA 在 50 任务平均表现仍存在显著 clean → randomized 落差：RDT 为 34.5% → 13.7%，Pi0 为 46.4% → 16.3%。这说明正式成绩不能只看 clean 成功率。`adjust_bottle` 等较容易任务可以作为贯通测试，但不能代表全部任务。

论文还表明：只用 clean 数据对已有模型做微调，对随机化场景的平均改善很有限；随机化预训练才带来明显改善。这个结论应当用于解释风险，而不是绕过“禁止使用 randomized 数据训练”的规则。

## 对比赛可执行的改进

下面按优先级排列。前四项是应先完成的工程与训练改进；后面项目必须保留对照实验，只有在 clean 验证集不退化时才保留。

### P0：先建立可信基线

1. **模型兼容性。** 核实 LingBot-VLA 2.0 的 6B 权重、processor、动作 token 格式、相机顺序、语言模板、机器人 state 维度和 checkpoint 加载方式。现有 XPolicyLab `LingBot_VLA` 适配器使用 Qwen2.5-VL-3B，不能直接视为 2.0 6B 适配完成。
2. **数据审计。** 固定清单为 `50 tasks × 50 clean episodes`；在训练前输出任务数、episode 数、相机 shape、动作/state 维度、缺失帧数和统计量。训练目录中不得出现 `randomized` 轨迹。
3. **单任务贯通。** 先以 `adjust_bottle` 跑通“转换 → 训练 → checkpoint → 策略服务 → clean 与 randomized 推理”。此阶段只验证工程，不以其成绩选择最终方案。
4. **单卡可运行。** 将评测配置的 `gpu_ids: "0-7"` 改为单卡；记录 ROCm、PyTorch、LingBot commit、配置 hash 和随机种子。

### P1：有限 clean 数据的训练策略

| 改进 | 做法 | 预期收益 | 验证方式 |
| --- | --- | --- | --- |
| 任务均衡采样 | 多任务训练时每个任务等概率采样，避免长轨迹或数据读取速度决定采样比例。 | 防止少数任务主导梯度。 | 记录每任务 batch 数和 loss。 |
| 两阶段训练 | 先做全部 50 任务的均衡适配，再针对低分任务做短轮次专项适配；保留可回滚的统一 checkpoint。 | 兼顾共享技能与难任务。 | 与“只做统一训练”比较每任务成功率。 |
| 任务分层 | 按单臂/双臂协作、抓取/放置/接力、精细定位等类别统计失败，不按任务名称盲目调参。 | 更快定位可复用问题。 | 每次 10 rollout 冒烟都产出失败标签。 |
| 动作与状态归一化 | 用训练集统计量统一位置、旋转、夹爪和关节状态尺度；双臂维度与左右顺序固定。 | 降低动作头数值不稳定和左右臂混淆。 | 保存统计文件；恢复 checkpoint 后得到相同输入输出尺度。 |
| 验证集纪律 | 每个任务暂留少量 clean episode 仅用于调参，确定配置后再用全部 50 条重新训练最终 checkpoint。 | 避免只对训练轨迹过拟合。 | 配置选择与最终训练分别留档。 |

### P2：允许范围内、但需谨慎的鲁棒性尝试

- **稳定的视觉预处理：** 明确 RGB/BGR、resize、裁剪、归一化、相机时间同步；这是数据处理一致性，不是新增数据。
- **语言模板一致化：** 让训练和评测使用相同的任务名称、对象命名和相机标识。若要加入同义指令模板，必须先向主办方确认其是否属于允许的数据处理，并在报告中完整记录。
- **轻量视觉增强：** 从 clean 图像生成亮度、颜色或裁剪扰动，可能被认定为变相随机化。默认不启用；只有获得明确规则解释后才进行消融并保留开关。
- **动作平滑：** 若 LingBot 输出动作 chunk，可比较最后一步、receding horizon 与时间加权聚合。论文中 ACT 的 temporal aggregation 用于提高部署稳定性，但它不能直接证明 LingBot 同样受益。所有方式必须满足控制频率和动作范围。
- **推理一致性：** 只在低延迟可承受时试验固定窗口观测、动作限幅、夹爪开闭滞回和安全裁剪；这些是推理策略，需逐项消融，不能掩盖模型失败。

### 不应采用的“改进”

- 不下载、转换或混入官方 `randomized` 轨迹进行训练、预训练、统计量计算或 checkpoint 选择。
- 不用论文的代码生成器额外采集并加入训练集，除非主办方书面允许；本赛题指定训练数据范围。
- 不把 randomized 正式测试结果反复当作训练信号。调参应以 clean 开发集为主，正式 100 次评测应在 checkpoint 固定后执行并记录。
- 不使用仿真中完美点云、背景分割或测试时不可获得的特权信息；论文中的 DP3 优势部分依赖精确点云和干净背景分割，不能当作 LingBot 图像 VLA 的可比基线。

## 建议的实验矩阵

先只在 `adjust_bottle` 上做下列实验。每次保存配置、seed、训练步数、checkpoint、10 次 clean 冒烟和 10 次 randomized 冒烟结果。通过后再扩展到 50 个任务。

| 编号 | 目的 | 改动 | 保留条件 |
| --- | --- | --- | --- |
| B0 | 工程基线 | 官方 clean 数据、默认 LingBot 配置 | 能稳定加载和完成 rollout。 |
| B1 | 数据正确性 | B0 + 数据审计与统一归一化 | loss 合理下降、clean 不退化。 |
| B2 | 动作稳定性 | B1 + 一种动作聚合/限幅策略 | clean 和 randomized 冒烟至少一项提升，另一项不明显下降。 |
| B3 | 多任务泛化 | B1 的任务均衡采样 | 50 任务平均优于非均衡采样。 |
| B4 | 难任务适配 | B3 + 短轮次专项适配或 adapter | 不牺牲已通过任务；checkpoint 与加载规则明确。 |

每次只改一项。若 B2/B4 没有可重复收益，回退至 B1/B3，不把复杂度带进最终提交。

## 评测与提交路线

1. 先完成 50 个任务的 clean 冒烟，检查任务名、加载权重、策略服务和结果落盘。
2. 固定 checkpoint 后，在每任务两种 setting 各运行 100 次，总计 10,000 次。
3. 对每任务保存成功数、失败类别、seed、日志路径和推理版本；再生成官方 `results.json`。
4. 最终提交中保留训练/评测脚本、配置、对应 checkpoint、数据处理统计、复现报告和该实验决策表。

## 与论文结论的对应关系

| 论文观察 | 本项目的可执行转化 |
| --- | --- |
| clean 微调无法自然获得 randomized 鲁棒性 | 把 randomized 视为主要风险；优先保证预训练模型兼容、数据管线正确和推理稳定。 |
| 随机化训练最有效 | 赛制禁止使用该数据，因此不采用；任何 clean 派生增强先确认规则。 |
| 低自由度 Aloha-AgileX 从自适应抓取中获益明显 | 训练侧重点应放在抓取接近、左右臂分工、位姿与夹爪动作的对齐。 |
| 视觉反馈可定位失败步骤 | 为 rollout 增加结构化失败记录，用于调试；不生成额外训练轨迹。 |
| 全任务平均随机化成绩远低于 clean | 不能以单一简单任务的 clean 成功率宣布完成，必须完成两种 setting 的完整评测。 |
